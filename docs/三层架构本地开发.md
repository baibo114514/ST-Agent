# 三层架构与本地混合开发

本项目现在按三层拆分：

1. `frontend/`：独立前端控制台，只访问主后端 API，默认端口 `5174`。
2. `app/`：主后端/control-plane，负责认证、平台 Agent 配置、普通用户 Agent 调用、knowledge-service 代理。
3. `services/knowledge_service/`：独立知识库微服务，负责知识库、文档、Chunk、入库任务和向量检索；开发环境默认使用外部 API（SiliconFlow）作为 embedding provider，无需本地 Ollama。

## 调用边界

```text
前端控制台
  -> /api/v1/auth/*
  -> /api/v1/admin/platform/agent-catalog
  -> /api/v1/admin/platform/knowledge-*
  -> /api/v1/agents/*
      |
      v
主后端 app/
  -> 保存平台 Agent 配置
  -> 代理知识库管理请求
  -> 运行前按 Agent 配置预检索并注入知识上下文
      |
      v
knowledge-service
  -> te_knowledge_base
  -> te_knowledge_document
  -> td_knowledge_chunk
  -> tl_knowledge_ingest_job
```

前端不直接连接 knowledge-service；LangGraph Runtime 也不直接管理知识库表。服务间请求使用 `X-KB-Service-Token`。

## 平台管理员流程

1. 注册或登录 `PLATFORM_ADMIN_EMAILS` 中的邮箱。
2. 在平台管理页创建知识库。
3. 上传 PDF 或文本类文档，knowledge-service 完成解析、切片、Embedding 和入库任务记录。
4. 创建平台 Agent，配置模型、角色说明、工具开关和知识库绑定。
5. 将 Agent 状态改为 `published`。

浏览器控制台支持单文件、多文件和目录上传。目录上传会把浏览器提供的相对路径写入 `sourceRef` 与 `metadata.relativePath`，重复上传同一路径会更新同一份文档。

宿主机本地目录也可以用脚本批量导入，例如把武创通政策文件导入 `policy` Agent 绑定的知识库：

```powershell
.\.venv\Scripts\python.exe scripts\ingest_directory.py --agent-code policy --directory "C:\Users\xzc\Desktop\test\武创通政策文件类\武创通政策文件类知识库" --dry-run
.\.venv\Scripts\python.exe scripts\ingest_directory.py --agent-code policy --directory "C:\Users\xzc\Desktop\test\武创通政策文件类\武创通政策文件类知识库" --limit 10
```

全量导入前建议先跑 `--dry-run` 和小批量 `--limit`，因为每个分片都会调用外部 embedding API。

长任务续跑建议带上 `--skip-existing`、重试和更长超时：

```powershell
.\.venv\Scripts\python.exe scripts\ingest_directory.py --directory "C:\Users\xzc\Desktop\test\武创通政策文件类\武创通政策文件类知识库" --kb-id eefc7633-a37a-456a-b3ba-0d5dfba61545 --concurrency 2 --skip-existing --retries 3 --timeout 600
```

## 普通用户流程

1. 登录后进入用户调用页。
2. 选择已发布 Agent。
3. 创建会话并发送消息。
4. 主后端读取 Agent 配置；如果启用知识库，会先调用 `/internal/v1/kb/search`，再把 `[知识库上下文]` 注入最后一条用户消息。

## 本地混合部署

Docker 运行基础设施，主代码在宿主机运行，方便断点调试。现在 Docker 启停和本地启停分开管理。

```powershell
# 1. 启动 Docker 基础设施：PostgreSQL/pgvector
scripts\start-docker.cmd

# 2. 启动本地三层服务：knowledge-service、主后端、前端
scripts\start-local.cmd
```

Windows 下也可以直接使用一键脚本：

```powershell
scripts\start-docker.cmd
scripts\start-local.cmd
scripts\stop-local.cmd
scripts\stop-docker.cmd
scripts\manage-local.cmd status
scripts\manage-docker.cmd status
```

脚本会把本地运行状态写入 `.runtime/local-services/`，Docker 状态由 `scripts\manage-docker.cmd` 单独管理。
只重启某一个本地服务时可以使用 `-Service`，例如：

```powershell
scripts\manage-local.cmd restart -Service knowledge-service
scripts\manage-local.cmd status -Service knowledge-service
```

（默认走外部 embedding API，无需本地模型与磁盘占用；如需本地 Ollama 再按需启动。）

访问地址：

- 前端控制台：http://127.0.0.1:5174
- 主后端文档：http://127.0.0.1:8000/docs
- knowledge-service 健康检查：http://127.0.0.1:8010/health
- Langfuse Cloud：https://cloud.langfuse.com

## 旧 RAG 配置迁移

旧版 `RAG_*` 环境变量不再由主后端读取，知识库配置统一迁移到独立 knowledge-service：

| 旧配置 | 新配置/处理方式 |
| --- | --- |
| `RAG_COLLECTION_NAME` | 不再使用单一 collection；在平台管理界面创建多个知识库，并通过 Agent 配置绑定知识库。 |
| `RAG_RERANKER_MODEL` | 改为 `KNOWLEDGE_RERANKER_MODEL`。如需启用 rerank，同时配置 `KNOWLEDGE_RERANKER_BASE_URL` 和 `KNOWLEDGE_RERANKER_API_KEY`。 |
| `RAG_UPLOAD_DIR` | 不再作为主后端配置；浏览器上传和目录入库由 knowledge-service 接收并写入数据库。 |
| `RAG_MAX_FILE_SIZE_MB` | 改为 `KNOWLEDGE_MAX_FILE_SIZE_MB`。 |

本地默认管理员邮箱是 `admin@example.com`。如果用自己的邮箱登录，需要同步修改 `PLATFORM_ADMIN_EMAILS`。

## API 对照

| 场景 | 前端调用主后端 | 主后端调用 knowledge-service |
| --- | --- | --- |
| 知识库健康 | `GET /api/v1/admin/platform/knowledge-health` | `GET /internal/v1/kb/health` |
| 知识库列表/创建 | `GET/POST /api/v1/admin/platform/knowledge-bases` | `GET/POST /internal/v1/kb/bases` |
| 文档列表 | `GET /api/v1/admin/platform/knowledge-bases/{kbId}/documents` | `GET /internal/v1/kb/bases/{kbId}/documents` |
| 文件上传 | `POST /api/v1/admin/platform/knowledge-bases/{kbId}/ingest/file` | `POST /internal/v1/kb/bases/{kbId}/ingest/file` |
| 入库任务 | `GET /api/v1/admin/platform/knowledge-ingest-jobs` | `GET /internal/v1/kb/jobs` |
| 搜索预览 | `POST /api/v1/admin/platform/knowledge-search` | `POST /internal/v1/kb/search` |
| 用户 Agent 列表 | `GET /api/v1/agents` | 不调用 |
| 用户 Agent 流式调用 | `POST /api/v1/agents/{agentId}/chat/stream` | 按 Agent 配置调用 `/internal/v1/kb/search` |

## Agent 知识配置

平台 Agent 的知识配置保存在 `platform_agent.config_json.knowledge`：

```json
{
  "enabled": true,
  "kbIds": ["knowledge-base-id"],
  "topK": 5,
  "scoreThreshold": 0
}
```

保存 Agent 时主后端会校验所有 `kbIds` 都存在且处于 `active`。运行时知识库检索由 Agent 通过 `knowledge_base_search` 工具按需调用，检索范围（kbIds/topK/scoreThreshold）通过图状态注入，不预先改写用户消息。空知识库会直接返回空检索结果，不会触发 embedding 调用。

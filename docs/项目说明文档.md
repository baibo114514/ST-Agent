# **📚 项目详细说明与架构白皮书**

## **1\. 项目概述 (Project Overview)**

本项目是一个基于 Python 编写的**生产级 AI Agent（智能体）后端服务**。

区别于简单的“一问一答”套壳 API，本项目深度融合了 **LangGraph**，赋予了 AI 状态管理、多轮思考、记忆留存以及动态调用第三方工具（Tools）的能力。配合 FastAPI 的高并发特性与 Langfuse 的深度可观测性，是一套完全达到企业级生产标准的框架。

## **2\. 核心技术栈 (Technology Stack)**

### **2.1 后端服务层**

* **Web 框架**: FastAPI (原生异步，极高吞吐量)  
* **运行服务器**: Uvicorn \+ uvloop  
* **路由控制**: APIRouter \+ 依赖注入机制  
* **认证机制**: JWT (JSON Web Token) \+ Bcrypt 密码哈希

### **2.2 AI 与智能体引擎层**

* **大模型网关**: LangChain (底层接口) \+ DeepSeek 官方 API  
* **智能体图编排**: LangGraph (状态机、Checkpoint机制、多路分支)  
* **模型高可用路由**: 自研 LLMService，结合 tenacity 实现指数退避重试与备用模型自动切换 (Failover)。

### **2.3 数据库与存储层**

* **关系型数据库**: PostgreSQL (存储用户、会话、线程等核心业务数据)  
* **向量数据库**: pgvector (PostgreSQL 插件，用于存储高维向量)  
* **ORM 框架**: SQLModel (结合了 Pydantic 和 SQLAlchemy 的现代框架)

### **2.4 可观测性与运维层 (Observability & DevOps)**

* **LLM 链路追踪**: Langfuse (精确到 Token 级别的使用量、成本和思考路径监控)  
* **结构化日志**: structlog (JSON 格式化，绑定 Request ID 与 User ID)  
* **容器化部署**: Docker \+ Docker Compose

## **3\. 核心功能模块剖析**

### **3.1 动态工具箱 (Dynamic Tool-Use)**

通过前端传入的 FeatureFlags，动态向大模型注入可用工具：

1. **网络搜索 (Web Search)**: 默认集成 Tavily API，当 Token 耗尽或无 Key 时，代码中内置了自动降级到 DuckDuckGo 的容灾方案。  
2. **代码沙盒 (Code Interpreter)**: 提供 Python REPL 环境，Agent 可以自行编写并运行代码，用于解决复杂数学计算或数据清洗。  
3. **长期记忆 (Long-Term Memory)**: Agent 可以自主判断是否需要将用户的个人偏好写入 Memory 表，并在后续对话中检索。  
4. **混合 RAG 检索**:  
   * **Ingest**: 接收 PDF/TXT，切片并调用 Embedding 模型存入 pgvector。  
   * **Retrieve**: 使用混合检索（向量查询）调取 Top-K 结果。  
   * **Rerank**: 调用 BGE-Reranker 模型进行二次重排，提取最精准的上下文。  
5. **邮件助手 (Email Assistant \- HITL)**:  
   * **核心亮点**: 引入了 Human-in-the-loop (人工审查) 机制。  
   * 发送邮件前，Agent 工作流会被 interrupt 挂起，直到前端调用 /api/v1/sessions/{sessionId}/resume 接口传入用户批准指令后，才调用 SMTP 协议真正发送邮件。

### **3.2 自研自动化评估系统 (Evals Module)**

项目内置了独立的检索评估子服务 `services/evaluation_service/main.py`，用于测试 knowledge-service 的政策文档召回、排序、片段锚点和业务权重指标。

* **数据来源**: 政策评估 JSONL、knowledge-service 文档目录和检索接口。
* **评估维度**: Recall@K、MRR、nDCG@K、片段锚点、武汉本地优先、时效性、产业相关性和负例拒答。
* **工作流**: 通过内部 API 黑盒调用 knowledge-service，在本地生成 JSON 和 Markdown 报告。

## **4\. 架构数据流图 (Data Flow)**

1. **客户端** 携带 JWT Token 发起 /api/v1/agents/{agentId}/chat/stream 请求。  
2. **FastAPI 中间件** 提取 Token，解析 user\_id 并将其绑定至日志上下文 (structlog)。  
3. **请求** 进入 agents.py，经 agent_config_service 解析出 messages、features 和 model_name。  
4. **LangGraph 引擎** 激活。加载之前存储在 PostgreSQL 里的 Checkpoint 恢复对话状态。  
5. **LLM 路由** 选择默认模型，若限流则自动切换备胎。LLM 决定是否调用工具。  
6. 若需审批（如发邮件），抛出流式中断信号，等待唤醒。  
7. 返回生成的文本流（Server-Sent Events），Langfuse 异步记录耗时与 Token。

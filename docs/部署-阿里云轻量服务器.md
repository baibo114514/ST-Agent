# 阿里云轻量服务器（2核2GB / 40GB）精简部署指南

本指南针对最低配（2核2GB内存）落地。核心原则：**只容器化数据库，三个 Python 服务跑宿主机，embedding 与 LLM 全部走外部 API，砍掉本地 Ollama、监控三件套与评估模块。**

## 一、精简后跑什么

| 组件 | 运行方式 | 端口 | 内存（估） |
|---|---|---|---|
| PostgreSQL + pgvector | Docker（`docker-compose.prod.yml`） | 127.0.0.1:5432 | ~400 MB |
| 主后端 control-plane | 宿主机 uvicorn（1 worker） | 127.0.0.1:8000 | ~500 MB |
| knowledge-service | 宿主机 uvicorn（1 worker） | 127.0.0.1:8010 | ~400 MB |
| 前端静态文件 | nginx 反代（静态 + `/api` 反代） | 80 | ~20 MB |
| embedding / LLM | 外部 API（SiliconFlow / DeepSeek） | 出网 | 0（本地） |

合计约 **1.4–1.8 GB**，配合 2GB swap 兜底，可稳定运行。

> 已砍掉：本地 Ollama（bge-m3，省 ~1.8GB）、Prometheus、Grafana、cAdvisor、Langfuse self-host（默认用 Cloud）、evals 评估模块。

## 二、服务器准备

### 1. 加 2GB swap（防 OOM）

```bash
fallocate -l 2G /swapfile || dd if=/dev/zero of=/swapfile bs=1M count=2048
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

### 2. 装 Docker（跑数据库）

```bash
curl -fsSL https://get.docker.com | sh
systemctl enable --now docker
```

### 3. 装 Python 3.13 + uv

```bash
# 用 uv 装 Python（隔离系统环境）
curl -LsSf https://astral.sh/uv/install.sh | sh
uv python install 3.13
```

## 三、部署步骤

### 1. 拉代码并切到精简分支

```bash
mkdir -p /opt && cd /opt
git clone https://github.com/Xzcgod/FastGraph-Agent-Engine.git fastgraph
cd fastgraph
git checkout slim-deploy
```

### 2. 配置环境变量

```bash
cp .env.production .env.production.local   # 复制生产模板为本地实际配置（.local 优先加载且不进 git）
vim .env.production.local                  # 在这里填真实密钥
```

必改项：`POSTGRES_PASSWORD`、`JWT_SECRET_KEY`（`openssl rand -hex 32`）、`OPENAI_API_KEY`、`KNOWLEDGE_EMBEDDING_API_KEY`（SiliconFlow key）、`PLATFORM_ADMIN_EMAILS`、`ALLOWED_ORIGINS`。`KNOWLEDGE_EMBEDDING_PROVIDER` 保持 `api`（生产走外部 API，见第七节）。

### 3. 启动数据库

```bash
docker compose --env-file .env.production -f docker-compose.prod.yml up -d
docker compose --env-file .env.production -f docker-compose.prod.yml ps   # 确认 db healthy
```

### 4. 装 Python 依赖

```bash
cd /opt/fastgraph
uv sync    # 安装项目依赖（pyproject.toml 无 extra，直接默认同步）
```

### 5. 用 systemd 跑两个服务

用 `tee` 一次性写入两个服务文件：

```bash
# 后端服务
sudo tee /etc/systemd/system/fastgraph-backend.service > /dev/null <<'EOF'
[Unit]
Description=FastGraph Backend (control-plane)
After=network.target docker.service

[Service]
WorkingDirectory=/opt/fastgraph
Environment=APP_ENV=production
ExecStart=/opt/fastgraph/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

# 知识库服务
sudo tee /etc/systemd/system/fastgraph-knowledge.service > /dev/null <<'EOF'
[Unit]
Description=FastGraph Knowledge Service
After=network.target docker.service

[Service]
WorkingDirectory=/opt/fastgraph
Environment=APP_ENV=production
ExecStart=/opt/fastgraph/.venv/bin/uvicorn services.knowledge_service.main:app --host 127.0.0.1 --port 8010 --workers 1
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

# 重载并启动（enable = 开机自启）
sudo systemctl daemon-reload
sudo systemctl enable --now fastgraph-backend fastgraph-knowledge
sudo systemctl status fastgraph-backend fastgraph-knowledge
```

关键点：

- `Environment=APP_ENV=production` —— 让应用加载 `.env.production`（及其更优先的 `.env.production.local`），否则按默认 development 读错配置。
- `ExecStart` 用绝对路径 `.venv/bin/uvicorn` —— systemd 不认 shell 的 PATH，必须写全路径。
- `After=docker.service` —— 保证数据库容器先启动。
- `--host 127.0.0.1` —— 只监听本机，由 nginx 反代访问（方案 A 下保持 127.0.0.1，勿改 0.0.0.0）。

### 6. 前端（nginx 反代）

nginx 同时 serve 前端静态文件并反代 `/api` 到后端，前端与 API 同源、无跨域，后端保持监听 `127.0.0.1` 无需改动。

#### 6.1 安装 nginx

```bash
# Debian/Ubuntu
sudo apt-get install -y nginx
# CentOS / Alibaba Cloud Linux
sudo yum install -y nginx
```

#### 6.2 写入配置

```bash
sudo tee /etc/nginx/conf.d/fastgraph.conf > /dev/null <<'EOF'
server {
    listen 80;
    server_name 47.122.117.96;          # 你的公网 IP，或留 _ 匹配所有

    root /opt/fastgraph/frontend;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;   # SPA 前端：文件找不到回退到 index.html
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
EOF
```

#### 6.3 删默认站点（避免 80 端口冲突）

nginx 自带 `default` 站点也监听 80，不删会抢端口，导致访问到默认页或 502：

```bash
sudo rm -f /etc/nginx/sites-enabled/default    # Debian/Ubuntu
sudo rm -f /etc/nginx/conf.d/default.conf      # CentOS/通用
```

#### 6.4 测试 + 重载 + 验证

```bash
sudo nginx -t                # 先测语法
sudo systemctl reload nginx  # 通过后重载

curl http://127.0.0.1/               # 应返回前端 index.html
curl http://127.0.0.1/api/v1/health  # 应返回后端健康 JSON
```

浏览器访问 `http://47.122.117.96/` 即可。前端 `config.js` 的 `apiBase` 默认为空（走同源 `/api` 相对路径），无需手动填；仅本地开发（前端 5174 / 后端 8000 分离）时才需要填 `http://127.0.0.1:8000`。

> 阿里云安全组只需放行 **80** 一个端口。`proxy_pass` 末尾**不加斜杠**（保留 `/api` 前缀），加了斜杠会剥掉 `/api` 导致后端路由错乱。

## 四、恢复数据库（可选，迁移现有系统）

把之前备份的 `agent_db_backup.dump` 传到服务器 `/opt/fastgraph/`，然后：

```bash
cd /opt/fastgraph
PW=$(grep -E "^POSTGRES_PASSWORD=" .env.production | head -1 | sed 's/^POSTGRES_PASSWORD=//' | sed 's/^"//;s/"$//')
# 先把备份文件传进容器再恢复（避免路径转换问题）
docker cp agent_db_backup.dump fastgraph-agent-engine-db-1:/tmp/agent_db_backup.dump
docker exec -e PGPASSWORD="$PW" fastgraph-agent-engine-db-1 \
  pg_restore -U postgres -d agent_db --clean --if-exists /tmp/agent_db_backup.dump
```

> 若数据库是全新空库（`agent_db` 已存在且无数据），去掉 `--clean` 更稳妥；若目标是覆盖，保留 `--clean --if-exists`。

## 五、验证

```bash
# 后端健康
curl http://127.0.0.1:8000/api/v1/health
# knowledge 健康
curl http://127.0.0.1:8010/internal/v1/kb/health -H "X-KB-Service-Token: <token>"
# 数据库可达
docker exec fastgraph-agent-engine-db-1 pg_isready -U postgres -d agent_db
```

前端登录 → 创建会话 → 发消息 → 知识库检索，确认全链路正常。若启用知识库，务必先按「embedding 改外部 API」后的说明**重新嵌入**存量文档（见下）。

## 六、运维

```bash
# 看日志
journalctl -u fastgraph-backend -f
journalctl -u fastgraph-knowledge -f

# 重启
systemctl restart fastgraph-backend fastgraph-knowledge

# 数据库备份（定期执行）
docker exec -e PGPASSWORD="$PW" fastgraph-agent-engine-db-1 \
  pg_dump -U postgres -d agent_db -F c -f /tmp/backup.dump
docker cp fastgraph-agent-engine-db-1:/tmp/backup.dump /opt/backups/backup-$(date +%F).dump
```

## 七、⚠️ embedding 提供方与重新嵌入

### 7.1 provider 开关

knowledge-service 通过 `KNOWLEDGE_EMBEDDING_PROVIDER` 自主选择嵌入提供方：

| 取值 | 端点 | 模型 | 适用 |
|---|---|---|---|
| `local` | `http://127.0.0.1:11434/v1`（本地 Ollama） | `bge-m3` | 本地开发（零成本，需跑 Ollama） |
| `api` | `https://api.siliconflow.cn/v1` | `BAAI/bge-m3` | 生产（本指南，省内存） |

生产 `.env.production` 已设 `KNOWLEDGE_EMBEDDING_PROVIDER=api`，无需改动；若要本地跑 Ollama，改 `local` 并在 docker-compose 里起 ollama。

### 7.2 切换后必须重新嵌入

本地 Ollama `bge-m3` 与 SiliconFlow `BAAI/bge-m3` 的向量**不可混用**。切换 provider 后存量知识库向量全部失效，需清空 `td_knowledge_chunk` 后重新上传文档入库，否则检索结果错误。顺序：改配置 → 清空 → 重新入库 → 再开放检索。

## 八、更新部署（从远端拉取代码）

代码在 `/opt/fastgraph` 直接 `git clone` 而来，更新 = 拉远端 + 重装依赖 + 重启服务。前端是纯静态文件由 nginx 直接 serve，代码更新后**自动生效、无需额外操作**；`.env.production.local` 不进 git，拉取不会覆盖你的本地密钥配置。

### 8.1 拉取最新代码

服务器上的代码目录是只读部署副本，推荐用 `fetch + reset` 强对齐远端，避免本地残留改动导致 `git pull` 冲突：

```bash
cd /opt/fastgraph
git fetch origin
git checkout slim-deploy
git reset --hard origin/slim-deploy
```

> 若确认本地没有手动改动，`git pull origin slim-deploy` 也可；`reset --hard` 更稳妥，会丢弃本地对已跟踪文件的任何改动（`.env.production.local` 等未跟踪文件不受影响）。

### 8.2 重装依赖

远端可能新增或升级了依赖，每次更新都跑一次 `uv sync`（幂等，无变更则秒过）：

```bash
cd /opt/fastgraph
uv sync
```

### 8.3 重启服务

重启会触发 `init_database` 自动建表/补列（幂等 `CREATE TABLE IF NOT EXISTS` / `ADD COLUMN IF NOT EXISTS`），无需手动迁移 schema：

```bash
sudo systemctl restart fastgraph-backend fastgraph-knowledge
sudo systemctl status fastgraph-backend fastgraph-knowledge   # 确认 active (running)
```

### 8.4 存量文档元数据迁移（仅在涉及知识库元数据字段变更时）

若远端更新包含知识库元数据提取相关改动（如新增 `metadata_extraction_json` 列、文档 metadata 结构变更），需对存量文档回填规范化 metadata：

```bash
cd /opt/fastgraph
APP_ENV=production .venv/bin/python scripts/migrate_metadata.py --dry-run          # 先预览会改多少条
APP_ENV=production .venv/bin/python scripts/migrate_metadata.py                    # 确认无误后真正落库
```

- `--kb-id <ID>` 可重复传入，只迁移指定知识库；不传则迁移全部。
- 脚本幂等：已是最新结构（`normalized == current`）的文档会被跳过。
- 若更新说明未提及元数据字段变更，可跳过本步。

### 8.5 更新后验证

```bash
curl http://127.0.0.1:8000/api/v1/health
curl http://127.0.0.1:8010/internal/v1/kb/health -H "X-KB-Service-Token: <token>"
```

前端浏览器强刷（Ctrl+F5）后按「五、验证」走一遍登录 → 会话 → 检索全链路即可。
